# Guitar Fretboard Scale Visualizer

## 1. Что это и для кого

Guitar Fretboard Scale Visualizer — небольшой веб-сервис на FastAPI для гитаристов, басистов и студентов, изучающих музыкальную теорию. Он показывает, где на грифе расположены ноты выбранной гаммы, с учётом пользовательского строя и тональности. Сервис помогает видеть гамму на грифе при любом поддерживаемом строе. Интерфейс работает в обычном браузере, а вычисления также доступны через JSON API.

## 2. Возможности

- Пользовательский строй на 4–8 струн.
- Семь ладов/типов гамм: major, minor, pentatonic major, pentatonic minor, blues, dorian и mixolydian.
- Чёрно-белая автономная SVG-визуализация без внешних ресурсов.
- Подсветка тоник и остальных нот выбранной гаммы.
- HTML-страница с GET-формой и JSON API, включая Swagger UI.
- Пресеты гитарных, басовых и укулеле-строёв.

## 3. Установка

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
```

Скопируйте пример настроек при необходимости:

```bash
cp .env.example .env
```

Приложение читает переменные среды через `os.getenv`; само по себе оно не загружает файл `.env`. Чтобы использовать значения из `.env`, экспортируйте их в окружение выбранным способом либо задайте непосредственно перед запуском. Файл `.env` исключён из Git.

## 4. Запуск

```bash
uvicorn app_final:app --host 0.0.0.0 --port 8000
```

Для обычной работы запускайте **без `--reload`**. Флаг `--reload` предназначен для локальной разработки и не нужен для демонстрации стабильного запуска.

## 5. Как открыть

- Страница визуализатора: <http://localhost:8000/>
- Swagger / интерактивная документация API: <http://localhost:8000/docs>
- Проверка готовности: <http://localhost:8000/health>

В форме введите ноты открытых струн через запятую в порядке **от самой низкой струны к самой высокой** (для стандартной гитары это `E2,A2,D3,G3,B3,E4`). Низкая струна отображается снизу грифа, высокая — сверху.

## 6. Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_VERSION` | `0.1.0` | Версия в `/version` и стартовом логе |
| `DEFAULT_TUNING` | `E2,A2,D3,G3,B3,E4` | Строй по умолчанию |
| `DEFAULT_ROOT` | `C` | Тоника по умолчанию |
| `DEFAULT_MODE` | `major` | Гамма по умолчанию |
| `DEFAULT_FRETS` | `12` | Число ладов по умолчанию |
| `NOTATION` | `sharps` | Запись нот: `sharps` или `flats` |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

Шаблон уже содержит эти ключи без секретов. Создайте локальную копию командой `cp .env.example .env`; не добавляйте настоящий `.env` в Git. Невалидные настройки окружения заменяются безопасными значениями по умолчанию.

## 7. Примеры API-запросов

Проверить здоровье сервиса:

```bash
curl http://localhost:8000/health
```

Получить версию:

```bash
curl http://localhost:8000/version
```

Запросить сетку грифа:

```bash
curl 'http://localhost:8000/fretboard?tuning=E2,A2,D3,G3,B3,E4&root=C&mode=major&frets=12&notation=sharps'
```

Получить SVG:

```bash
curl -o fretboard.svg 'http://localhost:8000/fretboard.svg?tuning=E2,A2,D3,G3,B3,E4&root=C&mode=major&frets=12&notation=sharps'
```

Получить ноту на пятом ладу шестой струны (индекс струны `0`):

```bash
curl 'http://localhost:8000/note?tuning=E2,A2,D3,G3,B3,E4&string=0&fret=5&notation=sharps'
```

Получить пресеты строёв:

```bash
curl http://localhost:8000/tunings
```

Сокращённый пример ответа `/fretboard`:

```json
{
  "tuning": ["E2", "A2", "D3", "G3", "B3", "E4"],
  "root": "C",
  "mode": "major",
  "frets": 12,
  "notation": "sharps",
  "scale_pitch_classes": [0, 2, 4, 5, 7, 9, 11],
  "root_pitch_class": 0,
  "grid": [
    [
      {"fret": 0, "note": "E", "pitch_class": 4, "is_root": false, "in_scale": true},
      {"fret": 1, "note": "F", "pitch_class": 5, "is_root": false, "in_scale": true}
    ]
  ]
}
```

В полном ответе `grid` содержит все струны, а на каждой струне — позиции от открытой струны (`fret: 0`) до заданного количества ладов включительно. В параметре `tuning` можно передать ключ пресета, например `standard`, или собственный список нот. Индексы `string` в `/note` начинаются с нуля и идут в том же порядке, что и строй.

## 8. Как читать SVG

- **Чёрный кружок с белой буквой** — тоника выбранной гаммы.
- **Светло-серый кружок с чёрной буквой** — другая нота гаммы.
- **Белый кружок с чёрной обводкой без буквы** — нота вне гаммы.
- Струны горизонтальные, лады вертикальные; порожек толще остальных линий.
- Низкая струна `tuning[0]` находится снизу, высокая последняя струна — сверху.
- Подписями ладов отмечены позиции от `0` (открытая струна) до выбранного значения `frets`.

SVG встроен в HTML на главной странице и выдаётся отдельно через `/fretboard.svg` с типом `image/svg+xml`. Изображение масштабируется благодаря `viewBox` и не использует внешние шрифты или картинки.

## 9. Тесты

Запуск полного набора:

```bash
python -m pytest -v
```

В наборе 12 быстрых тестов без доступа к сети: проверка health/version, пресетов строёв, расчёта стандартного грифа и C major, позиции отдельной ноты, обработки неизвестного лада и невалидного строя, SVG, HTML-страницы и ошибок пользовательского ввода. Тесты используют `fastapi.testclient.TestClient`.

## 10. Логи и диагностика

Логи выводятся в стандартный поток процесса, поэтому при запуске из терминала их видно сразу, а в CI они доступны в выводе job. При старте журналируются версия и строй по умолчанию. Запросы к грифа/API и ошибки валидации также логируются; неожиданные исключения сопровождаются traceback.

Для более подробной диагностики задайте `LOG_LEVEL=DEBUG` перед запуском, например:

```bash
LOG_LEVEL=DEBUG uvicorn app_final:app --host 0.0.0.0 --port 8000
```

При создании issue укажите шаги воспроизведения, URL и query-параметры без секретов, ожидаемый результат, фактический результат и соответствующий фрагмент лога. Не прикладывайте пароли, токены или приватный `.env`.

## 11. CI

Workflow находится в [`.github/workflows/ci.yml`](.github/workflows/ci.yml). GitHub Actions устанавливает Python 3.11 и зависимости, запускает `python -m pytest -v`, а **только после успешного прохождения тестов** загружает артефакт `app-files` с `app_final.py`, `requirements.txt` и `requirements-dev.txt`.

После добавления проекта в GitHub откройте вкладку **Actions**, чтобы проверить результат последнего запуска и скачать артефакт из успешного workflow.

## 13. Ограничения

- Нет базы данных, Docker, frontend-фреймворков и внешних API.
- HTML формируется на сервере, форма использует обычный `GET`; JavaScript для перерисовки не нужен.
- Приложение визуализирует гаммы, но не рассчитывает аппликатуры аккордов и не генерирует табулатуры, звук или MIDI.
- Энгармонизм упрощён: имена нот отображаются через глобальную настройку `notation` (`sharps` или `flats`), без автоматического выбора написания по тональности.
- Номер лада в `/fretboard` ограничен диапазоном 1–24; `/note` принимает позицию от открытой струны до 24-го лада включительно.
- Строй должен содержать от 4 до 8 нот в порядке, в котором пользователь нумерует струны: от низкой струны к высокой.
